# 03 · 反幻觉护栏（运行时落地）

> 背景：Atlas 有过 LLM 编造数据的生产事故（GLM 虚构调休日 `2026-04-26`，官方根本没有该补班日）。这是本项目对 LLM 的根本不信任来源。本文把"LLM 在边缘"原则落成具体的运行时规则与 prompt 约束。

---

## 1. 总原则

LLM 在本灯塔只有两个职责，**均不接触数据正确性**：
- **边缘 1 · 意图解析**：自然语言 → 结构化意图（只做"听懂"）。
- **边缘 2 · 结果叙述**：结构化 diff/风险 → 自然语言（只做"复述"）。

日期、级联、撞节点的计算全在确定性代码里。LLM 说错最多是表达不准，碰不到数据。

---

## 2. 边缘 1（意图解析）的硬约束

**结构性约束（代码层，不依赖 prompt 自觉）**
- 输出必须通过 `ScheduleChangeIntent` 的 Zod 校验，否则视为失败。
- `activityId`/`dependsOnId` 解析后**逐个校验**是否在"本次传入的活动清单"内；任何不在清单内的 id → 直接判失败（不是信任 LLM 不编，而是代码兜底拦截）。
- 解析结果为空操作 → 走"没听懂"降级，不进入干跑。

**prompt 约束（要点）**
- 明确：你只能从下面这份活动清单里选择 activityId，清单里没有的活动，放进 `unresolved` 数组原样回传，**绝对不要编造或猜测一个 id**。
- 明确：你**不负责计算任何日期或顺延**，只输出"用户想做什么操作"。日期由系统计算。
- 明确：如果用户的话你无法可靠地映射到具体操作，宁可返回空操作并说明，也不要猜。
- 明确：对自己的解析有把握就 `confidence: high`，含糊就 `confidence: low`。
- 反例锚定（沿用项目惯例）：举 `2026-04-26` 编造事故为戒——"编造一个看似合理实则不存在的东西，是最严重的错误；不确定就报告不确定"。

---

## 3. 边缘 2（结果叙述）的硬约束

**结构性约束**
- 叙述的输入**只有**结构化 diff + RiskFinding。不向 LLM 提供"可自由发挥"的上下文。
- 叙述仅用于展示；即便叙述出错或 AI 宕机，用户仍基于**结构化 diff 表 + 风险标记**做决定（见 `01` §G）。也就是说叙述是"锦上添花"，不是决策依据。

**prompt 约束（要点）**
- 明确：只复述下面给你的改动和风险，**不得新增任何事实、数字、日期、风险或建议**。
- 明确：不要安抚、不要承诺、不要推测"可能还有别的风险"；给了什么就说什么。
- 明确：如果改动列表为空或风险为空，如实说"无改动/无风险"。

---

## 4. 降级规则（不可伪造）

| 情形 | 行为 |
|---|---|
| circuitBreaker 打开（AI 不可用） | propose 返回"AI 助手暂不可用，请手动调整"，不伪造意图/叙述 |
| 意图解析失败/空/全 unresolved | "没听懂"+ 回显 unresolved，不瞎改 |
| 低置信 confidence='low' | 照常预览，但前端醒目警示请逐条核对 |
| 叙述阶段 AI 不可用 | 仅展示结构化 diff + 风险标记，仍可确认应用 |

核心：**任何不确定，都向用户暴露不确定，绝不用一个看似合理的输出掩盖。**

---

## 5. 审计（让幻觉可追溯）

应用时记录 `rawUtterance`（用户原话）+ `resolvedIntent`（解析意图）+ `appliedDiff`（实际改动）。一旦事后发现某次对话改错了，能还原"用户说了什么 → AI 解析成什么 → 实际改了什么"，并回滚。
