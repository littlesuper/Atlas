# 00 · 总体方向、设计哲学与现有架构

## 1. 这一轮 AI 赋能的方向

把 AI 能力嵌入 Atlas 产品本身，首要价值是**提升项目经理的工作效率**——让 PM 用自然语言调整排期并即时看到风险，把"改一个日期 → 手动顺延一串依赖 → 自己核对有没有撞节点"压缩成"一句话 + 一次确认"。

LLM 部署：**云端 API**，可接受内部数据出 LAN（仍遵循字段最小化，见 §4）。

推进方式：总体蓝图 + 第一个灯塔先行。本包就是第一个灯塔。

---

## 2. 不可妥协的设计哲学

Atlas 服务的是**非技术团队**，且有过 **LLM 编造数据的生产事故**（GLM 虚构调休日 `2026-04-26`）。这两点决定了任何 AI 功能都必须满足：

1. **永不静默改写权威数据。** AI 只能"提议"，写入必须经过人工确认这道闸门。
2. **永远展示来源与置信度。** 让用户能区分"这是 AI 的猜测"与"这是从你录入的数据算出来的事实"。
3. **一切 AI 动作可审计、可回滚。** AI 引发的写入走和人一样的、带审计日志的校验写入路径，不走旁路。
4. **宁可报告不确定，也不编造。** 复用项目里已固化的反幻觉护栏，搬进运行时（见 `03`）。

---

## 3. 核心架构原则：LLM 在边缘，确定性引擎在核心

这是整个灯塔能安全落地的关键。

**反模式（危险）**：让 LLM 直接理解请求、自己算新日期、自己判断级联、自己写库——任何一步幻觉都会污染权威数据，而非技术用户无法察觉。

**本包模式（安全）**：把"AI 改数据"拆成三段，LLM 只待在两端，核心交给确定性代码：

```
 PM 自然语言
   │
   ▼  ┌─ LLM 意图解析（边缘）──────────────────────────┐
   │  │ 自然语言 → 结构化「变更意图」                    │
   │  │ · 只能从"本项目活动清单"里选 activityId，不得编造 │
   │  │ · 输出受 Zod 约束；解析不出来 → 明确说"没听懂"     │
   ▼  └────────────────────────────────────────────────┘
 结构化意图
   │
   ▼  ┌─ 排期引擎 + 风险判定（确定性核心，非 LLM）──────┐
   │  │ · 调度器"干跑"算出假设排期（before/after diff）   │
   │  │ · 确定性判定：是否撞里程碑/硬节点/超期            │
   ▼  └────────────────────────────────────────────────┘
 结构化 diff + 风险清单
   │
   ▼  ┌─ LLM 结果叙述（边缘）──────────────────────────┐
   │  │ 结构化结果 → 自然语言解读                         │
   │  │ · 内容 100% 来自 diff/风险，不得新增任何事实/数字 │
   ▼  └────────────────────────────────────────────────┘
 自然语言预览 + 结构化 diff 表
   │
   ▼ PM 看预览 → 整批确认 → 走现有校验写入路径（审计 + 回滚）
```

**为什么这条消掉幻觉风险**：日期、级联、撞节点这些"事实"全由确定性代码产生，LLM 碰不到。LLM 说错最多是"表达不准"（PM 能从 diff 表里一眼看出），碰不到数据正确性。问题从"信任 LLM 算对"降级为"信任 LLM 把已经算对的结果翻译通顺"。

---

## 4. 横切关注点

- **幻觉**：§3 结构性消解 + `03` prompt 护栏 + 结构化输出 Zod 校验，三重。
- **成本/延迟**：云端 API 按调用计费；本地计算（干跑、风险判定）很快，LLM 往返是主要延迟来源 → 前端给"思考中"反馈；意图相同可缓存。
- **数据出域**：只把意图解析/叙述**必需**的字段发给云端（活动名、id、相关日期），不整库外发。
- **复用现有 AI 基建**：所有 LLM 调用必须经现有 `utils/circuitBreaker.ts`；source 标识沿用现有 `ai`/`rule_engine` 模式的风格。

## 5. 现有架构发现（来自项目文档，**属契约级假设，step-0 须核实**）

灯塔不是空地，Atlas 已有成熟的排期与风险基础设施：

- **依赖调度器（确定性）**：已设置前置依赖的活动，计划时间禁止手改，由调度器自动计算。→ 级联逻辑已存在。
- **依赖校验器** `server/src/utils/dependencyValidator.ts`：DFS 三色标记做循环依赖检测，写 `dependencies` 时跑。
- **风险引擎（双通道）**：AI 可用 `source: ai`，不可用回退规则引擎 `source: rule_engine`，规则引擎有加分表；定时任务 `scheduled_ai/scheduled_rule`。
- **AI 熔断器** `utils/circuitBreaker.ts`：所有 AI 调用都经它。
- **周报↔风险联动**：周报唯一约束 `[projectId, year, weekNumber]`，按 title 去重创建 `RiskItem(source='weekly_report')`。
- **目录约定**：新模型 `server/prisma/schema.prisma`；新路由 `server/src/routes/<模块>.ts` 并在 `index.ts` 挂载 `/api/<模块>`；Zod 校验 `server/src/schemas/<模块>.ts` + `validate(schema)` 中间件；工具 `server/src/utils/`；前端页面 `client/src/pages/`、类型 `client/src/types/index.ts`、API `client/src/api/`、常量/枚举中文与颜色 `client/src/utils/constants.ts`。
- **生产数据库迁移**：用 `prisma migrate deploy`（不是开发期的 `db push`）。

> 灯塔的设计正是建立在"复用上述确定性核心 + 现有 AI 基建"之上。`01` 会逐项说明哪些复用、哪些新建。
