# 04 · 意图解析测试集骨架

> 用途：为边缘 1（意图解析）建评测/契约测试。Claude Code 据此补全，并按真实活动 id 替换占位。
> 形式：每条 = 自然语言输入 + 给定活动清单 + 期望的结构化意图（或期望的降级行为）。
> 负样本与边界样本和正样本一样重要——它们验证"不编造、报告不确定"。

约定占位活动清单（测试用）：
```
A1 = 硬件打样
A2 = 固件联调   (依赖 A1)
A3 = 整机测试   (依赖 A2)
M1 = 验收里程碑 (里程碑, 依赖 A3, 硬节点=2026-08-03)
```

---

## 正样本（应解析成明确意图）

| # | 输入 | 期望意图（要点） |
|---|---|---|
| P1 | 把硬件打样推迟两周 | `shift_activity A1 +14`，confidence high |
| P2 | 硬件打样提前 3 天 | `shift_activity A1 -3` |
| P3 | 把整机测试的工期改成 5 天 | `set_duration A3 5` |
| P4 | 固件联调最晚 7 月 10 号结束 | `set_planned A2 end 2026-07-10` |
| P5 | 让整机测试依赖固件联调 | `add_dependency A3 dependsOn A2`（若已存在，见 E 边界） |
| P6 | 取消固件联调对硬件打样的依赖 | `remove_dependency A2 dependsOn A1` |
| P7 | 打样推迟两周，后面依赖的都顺延 | `shift_activity A1 +14`（顺延由调度器算，意图里**不该**出现对 A2/A3 的显式改动） |

> P7 是核心校验点：LLM **不应**自己枚举下游顺延，那是调度器的事。意图只表达"动 A1"。

---

## 负样本（应"没听懂"或进 unresolved，**不得编造**）

| # | 输入 | 期望行为 |
|---|---|---|
| N1 | 把"包装设计"推迟一周 | 清单无此活动 → `unresolved: ["包装设计"]`，空操作 / 提示没听懂 |
| N2 | 优化一下整个项目的节奏 | 无可执行操作 → "没听懂"，不得臆造一堆 shift |
| N3 | 帮我把项目按时交付 | 无具体操作 → "没听懂"，**绝不**自己编造日期去"凑"交付 |
| N4 | 把打样改到下个吉日 | 含糊不可执行 → "没听懂"或要求明确日期，不猜 |

---

## 边界 / 低置信样本

| # | 输入 | 期望行为 |
|---|---|---|
| B1 | 把那个测试往后挪挪 | "测试"可能指 A3；"挪挪"无明确量 → confidence low，或要求明确天数 |
| B2 | 打样和联调都推迟两周 | 两条 `shift_activity`（A1 +14, A2 +14）；注意 A2 依赖 A1，应用后是否冲突交给调度器/校验器 |
| B3 | 让验收里程碑依赖整机测试（已存在该依赖） | 识别为已存在 → 提示无需改动，或返回空操作 |
| B4 | 把整机测试依赖验收里程碑 | 会形成环（M1 已依赖 A3）→ 意图可解析，但应用阶段 dependencyValidator 必须拒绝（见 01 §J-9） |

---

## 风险判定相关（确定性，非 LLM，但需端到端覆盖）

| # | 场景 | 期望 |
|---|---|---|
| R1 | A1 +14 导致 M1 推过 2026-08-03 | `hard_node_breach`（M1，deadline 08-03，projected 晚于） |
| R2 | A1 +2，M1 仍早于 08-03 | 无 hard_node_breach |
| R3 | A1 推迟使里程碑 M1 计划日变化 | `milestone_slip`（M1 before→after） |
| R4 | 改动使项目预计结束晚于项目截止 | `project_overdue` |

---

## 使用建议

- 解析层尽量与具体 LLM 解耦：把"活动清单 → prompt → 期望结构化意图"做成可离线运行的契约测试，换模型时跑回归（呼应 00 §"评估优于假设"）。
- 负样本（N、B4）是反幻觉的主战场，覆盖率不能低于正样本。
