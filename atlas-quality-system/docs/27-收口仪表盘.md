# 收口仪表盘

> 用途：一条命令聚合 Week 8 最后 1% 的状态，避免在 blocker、resolution、owner 分派、证据包、证据交接、evidence intake、剩余工作、请求包、收口顺序和最终归档之间来回翻 JSON。

## 生成命令

```bash
npm run quality:closure-dashboard --workspace=server
```

默认输出 `QUALITY_CLOSURE_DASHBOARD` JSON，包含：

| 字段 | 含义 |
| --- | --- |
| `summary.total` | 纳入仪表盘的检查项数量 |
| `summary.ready` | 已达到 expectedStatus 的数量 |
| `summary.actionRequired` | 尚未达到 expectedStatus 的数量 |
| `currentFocus` | 当前最应该处理的一项 |
| `checks` | 所有检查项、命令、当前状态、期望状态和下一步 |

## 默认检查项

| 检查项 | 当前默认状态 | 期望状态 |
| --- | --- | --- |
| blocker register | `ACTION_REQUIRED` | `CLEAR` |
| blocker resolution | `ACTION_REQUIRED` | `RESOLVED` |
| closure evidence pack | `READY` | `READY` |
| closure evidence handoff | `READY` | `READY` |
| owner assignments | `ACTION_REQUIRED` | `READY` |
| evidence intake | `ACTION_REQUIRED` | `READY_TO_CONFIRM` |
| closure remaining work | `ACTION_REQUIRED` | `READY` |
| closure request pack | `ACTION_REQUIRED` | `READY` |
| closure sequence | `WAITING_FOR_EVIDENCE` | `READY_TO_ARCHIVE` |
| final closure | `ACTION_REQUIRED` | `READY_TO_ARCHIVE` |

## 使用方式

1. 运行 `quality:closure-dashboard` 看当前焦点。
2. 按 `currentFocus.command` 执行或分派。
3. 阻塞项已清除或已接受后，依次运行 `quality:closure-evidence-pack`、`quality:closure-evidence-handoff`、`quality:closure-remaining-work`、`quality:closure-request-pack`、`quality:evidence-intake`、`quality:team-confirmations` 和 `quality:final-closure`。
4. 最后用 `quality:progress-guard` 回填看板证据。

当所有检查项都达到 expectedStatus 时，仪表盘输出 `READY`。
