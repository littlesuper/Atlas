# 收口证据包

> 用途：把 Week 8 最后 1% 需要人工回填的证据，整理成固定字段和可复制命令。它不伪造真实证据，只提供证据槽位、owner、截止日期和 `quality:evidence-intake` 命令骨架。

## 生成命令

```bash
npm run quality:closure-evidence-pack --workspace=server
```

默认输出 `QUALITY_CLOSURE_EVIDENCE_PACK` JSON。

## 默认证据槽位

| 主题 | Owner | 截止日期 | evidenceRef 模板 |
| --- | --- | --- | --- |
| 质量回顾会实会确认 | AI 代码守护人 | 2026-05-08 | `quality-review-minutes#2026-05-08` |
| 分支保护和 PR 审查规则 | 产品负责人 | 2026-05-10 | `github-settings#branch-protection` |
| rebase/merge 策略 | release owner | 2026-05-08 | `release-notes#merge-plan` |

## 输出内容

| 字段 | 含义 |
| --- | --- |
| `requirements` | 每条人工证据的 topic、owner、dueDate、decisionTemplate 和 evidenceRefTemplate |
| `confirmArg` | 单条证据可直接传给 `quality:evidence-intake` 的 `--confirm` 参数 |
| `nextCommand` | 所有证据槽位拼好的 `quality:evidence-intake` 命令 |
| `gaps` | 缺少 owner、截止日期、决策模板或 evidenceRef 模板时的阻塞说明 |

## 完成标准

所有证据槽位字段齐全时，输出：

```text
QUALITY_CLOSURE_EVIDENCE_PACK / READY
```

随后把 `nextCommand` 中的模板值替换为真实会议纪要、GitHub Settings 截图/链接和 release 合并策略记录，再运行 `quality:evidence-intake`。
