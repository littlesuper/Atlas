**当前状态：** TODO 0%
**前置条件：** 生产数据库访问权限、GitHub 仓库 admin 权限

### 执行步骤

1. **GitHub 历史密钥扫描：**
   ```bash
   # 安装 gitleaks
   brew install gitleaks
   # 扫描仓库历史
   cd /Users/macbot/PlayCode/Atlas
   gitleaks detect --source . --verbose
   ```
2. **如发现泄露密钥：**
   - 立即轮换泄露的 secret（JWT_SECRET、AI_API_KEY 等）
   - 使用 `git filter-repo` 或联系 GitHub Support 清除历史
3. **权限审计：**
   ```bash
   # 检查 server/.env 中是否有硬编码密钥
   cat server/.env
   # 确认 .gitignore 覆盖了 .env
   git check-ignore server/.env
   ```
4. **生产环境检查：**
   - 确认生产环境使用环境变量而非硬编码
   - 确认 JWT_SECRET 和 JWT_REFRESH_SECRET 足够长（≥32 字符）
   - 确认 AI_API_KEY 未提交到仓库

### 完成标准

- [ ] `gitleaks detect` 报告 0 findings
- [ ] `server/.env` 已被 `.gitignore` 覆盖

## 5. 集成 AI Code Review

**当前状态：** TODO 0%
**前置条件：** 分支保护已设置（步骤 2）、AI API 可用

### 执行步骤

1. 选择 AI Code Review 工具（推荐选项）：
   - **GitHub Copilot Code Review**：GitHub 原生，最简集成
   - **CodeRabbit**：支持自定义规则，免费 tier 可用
   - **自建 GitHub Action**：调用 AI API 分析 PR diff
2. 如选择 GitHub Action 方案：
   ```yaml
   # .github/workflows/ai-review.yml
   name: AI Code Review
   on:
     pull_request:
       types: [opened, synchronize]
   jobs:
     review:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - name: AI Review
           # 根据选择的工具配置
   ```
3. 在 PR 审查流程中增加 AI review 作为参考（不阻断合并）

### 完成标准

- [ ] AI Code Review 工具已配置
- [ ] 新 PR 自动触发 AI 审查评论
