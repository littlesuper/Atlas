# 阻塞项接受记录

> 用途：当团队选择“接受阻塞并继续归档”时，记录 acceptedBy、接受理由、到期日和证据引用。没有这些字段时，不应认为阻塞已被接受。

## 默认命令

```bash
npm run quality:blocker-acceptance --workspace=server
```

默认要求以下 3 个阻塞项具备接受记录：

| 阻塞项 | 说明 |
| --- | --- |
| 质量回顾会实会确认 | 需要会议纪要或书面确认 |
| 分支保护和 PR 审查规则 | 需要远端设置证据或明确风险接受 |
| rebase/merge 策略 | 需要 release owner 记录策略 |

无接受记录时输出 `QUALITY_BLOCKER_ACCEPTANCE / ACTION_REQUIRED`。

## 接受阻塞

```bash
npm run quality:blocker-acceptance --workspace=server -- \
  --accept "分支保护和 PR 审查规则|产品负责人|2026-05-08|仓库管理员将在本周内完成设置，当前质量工具链可先归档|2026-05-15|quality-review-minutes#branch-protection-acceptance"
```

每个 `--accept` 的格式：

```text
item|acceptedBy|acceptedAt|rationale|expiresAt|evidenceRef
```

## 完成标准

所有 required blocker 都有完整接受记录时，输出：

```text
QUALITY_BLOCKER_ACCEPTANCE / ACCEPTED
```

该输出只能表示“风险被明确接受”，不能表示阻塞项已经实际清除。
