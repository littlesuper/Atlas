# 前七周质量复盘

> 用途：把 Week 1-7 的质量建设结果压缩成一份可归档、可进入质量回顾会的结构化报告，避免复盘只停留在口头总结。

## 生成命令

```bash
npm run quality:retro-report --workspace=server -- \
  --period "Week 1-7" \
  --week "Week 1|紧急止血|45|Sentry 最低错误追踪|分支保护未配置" \
  --week "Week 2|基础设施|100|CI 质量门禁,high audit 清零|" \
  --week "Week 3|开发流程|25|PR 模板|流程培训未执行" \
  --week "Week 4|单元测试与代码审查|100|ESLint warning 清零|" \
  --week "Week 5|集成测试与 E2E|100|P0/P1/P2 分层,a11y 覆盖|" \
  --week "Week 6|可观测性|90|metrics,alerts:check|APM 未选型" \
  --week "Week 7|发布与应急|100|灰度/回滚/应急工具包|" \
  --risk "团队侧流程未确认|main 落后远端 61 个提交" \
  --next-action "安排流程培训|规划 rebase/merge 策略"
```

## 周数据格式

`--week` 使用以下格式：

```text
周次|焦点|进度|成果1,成果2|缺口1,缺口2
```

示例：

```text
Week 6|可观测性|90|metrics,alerts:check|APM 未选型
```

## 输出字段

| 字段 | 说明 |
| --- | --- |
| `mode` | 固定为 `QUALITY_RETROSPECTIVE` |
| `status` | `PASSED` 或 `ACTION_REQUIRED`；存在未完成周或风险时为 `ACTION_REQUIRED` |
| `summary.averageProgress` | 周进度平均值 |
| `summary.completedWeeks` | 进度达到 100% 的周 |
| `summary.partialWeeks` | 仍需 Week 8 收口的周 |
| `weeks` | 每周焦点、成果和缺口 |
| `risks` | 跨周遗留风险 |
| `nextActions` | 后续行动项 |

## 当前复盘结论

- Week 2、Week 4、Week 5、Week 7 已形成相对完整的自动化证据链。
- Week 1、Week 3、Week 6 仍存在偏团队侧或外部系统侧缺口，适合放入 Week 8 稳定化 backlog。
- 已落地的命令型资产包括质量门禁、E2E 分层、可访问性、视觉回归、指标告警、事故上下文、发布门禁、灰度、回滚、演练和月度审计。
- 复盘报告的 `ACTION_REQUIRED` 不代表工具失败，而是明确提醒仍有流程、协作或外部平台事项需要人工闭环。
