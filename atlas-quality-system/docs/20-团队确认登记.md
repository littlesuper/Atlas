# 团队确认登记

> 用途：把 Week 8 仍需人工判断的事项变成可审计的证据门禁。没有证据引用时，命令保持 `ACTION_REQUIRED`。

## 默认检查事项

```bash
npm run quality:team-confirmations --workspace=server
```

默认要求以下 3 个主题具备确认记录：

| 主题 | 为什么需要人工确认 |
| --- | --- |
| 质量回顾会实会确认 | 需要团队实际确认行动项、季度目标和 owner |
| 分支保护和 PR 审查规则 | 需要仓库管理员在远端设置中落地 |
| rebase/merge 策略 | 当前 main 落后远端较多，需要 release owner 决策 |

无确认记录时，命令输出 `TEAM_CONFIRMATION_REGISTER / ACTION_REQUIRED` 并以非零状态退出。

## 登记格式

```bash
npm run quality:team-confirmations --workspace=server -- \
  --confirm "质量回顾会实会确认|AI 代码守护人|2026-05-08|确认 Week 8 action tracker 和季度目标|quality-review-minutes#2026-05-08" \
  --confirm "分支保护和 PR 审查规则|产品负责人|2026-05-10|由仓库管理员落地 GitHub Settings|github-settings#branch-protection" \
  --confirm "rebase/merge 策略|release owner|2026-05-08|确认 main 落后 61 个提交的收口策略|release-notes#merge-plan"
```

每个 `--confirm` 的格式为：

```text
topic|owner|confirmedAt|decision|evidenceRef
```

| 字段 | 要求 |
| --- | --- |
| `topic` | 必须匹配 required topic |
| `owner` | 必须填写确认负责人 |
| `confirmedAt` | 建议使用 `YYYY-MM-DD` |
| `decision` | 必须记录确认结论 |
| `evidenceRef` | 必须指向会议纪要、GitHub 设置截图、PR、审计附件或其他可追踪证据 |

## 自定义 required topic

如需额外纳入团队确认事项，可重复传入 `--required`：

```bash
npm run quality:team-confirmations --workspace=server -- \
  --required "质量回顾会实会确认" \
  --required "下一季度质量 owner 确认" \
  --confirm "下一季度质量 owner 确认|工程负责人|2026-05-08|确认 Q2 owner 和节奏|quarter-plan#owners"
```

## 完成标准

只有当所有 required topic 都有完整确认记录和 `evidenceRef` 时，命令才输出：

```text
TEAM_CONFIRMATION_REGISTER / CONFIRMED
```

该输出可作为 Week 8 最后收口、月度审计附件和下一季度计划启动的共同证据。
