# 质量阻塞项登记

> 用途：把剩余无法由代码自动完成的事项收敛为 owner、影响、下一步和证据要求。它是 Week 8 最后 1% 的执行清单。

## 生成命令

```bash
npm run quality:blocker-register --workspace=server
```

默认输出 `QUALITY_BLOCKER_REGISTER` JSON，当前包含 3 个人工阻塞项：

| 阻塞项 | Owner | 严重级别 | 证据要求 |
| --- | --- | --- | --- |
| 质量回顾会实会确认 | AI 代码守护人 | HIGH | `quality-review-minutes#2026-05-08` |
| 分支保护和 PR 审查规则 | 产品负责人 | HIGH | `github-settings#branch-protection` |
| rebase/merge 策略 | release owner | MEDIUM | `release-notes#merge-plan` |

## 自定义登记

```bash
npm run quality:blocker-register --workspace=server -- \
  --blocker "分支保护和 PR 审查规则|产品负责人|Week 8 无法最终归档|由仓库管理员落地 GitHub Settings|github-settings#branch-protection|HIGH|OPEN"
```

每个 `--blocker` 的格式为：

```text
item|owner|impact|nextAction|evidenceRequired|severity|status
```

`severity` 仅允许 `HIGH`、`MEDIUM`、`LOW`。`status` 仅允许 `OPEN`、`CLEARED`。

## 输出判定

- `CLEAR`：所有阻塞项均已清除。
- `ACTION_REQUIRED`：仍有 open 阻塞项，但 owner、下一步和证据要求完整。
- `BLOCKED`：存在缺 owner、nextAction 或 evidenceRequired 的阻塞项。

`ACTION_REQUIRED` 可以作为会议分派输入；`BLOCKED` 不能进入最终收口。
