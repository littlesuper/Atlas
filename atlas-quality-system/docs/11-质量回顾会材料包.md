# 质量回顾会材料包

> 用途：把质量回顾会从“临时开会”变成有输入、有议程、有决策、有行动项 owner 的可执行流程。

## 生成命令

```bash
npm run quality:review-pack --workspace=server -- \
  --title "Atlas 质量回顾会" \
  --scheduled-for "2026-05-06T10:00:00+08:00" \
  --participant "AI 代码守护人|产品负责人|后端负责人" \
  --input "月度质量审计报告|READY|quality:audit-report" \
  --input "前七周复盘报告|READY|quality:retro-report" \
  --agenda "确认 Week 8 稳定化 backlog|AI 代码守护人|20" \
  --agenda "确认团队侧流程 owner|产品负责人|15" \
  --decision "是否把分支保护设为 Week 8 阻断项|产品负责人|是,否" \
  --action "规划 rebase/merge 策略|后端负责人|2026-05-08|Week 1-7 retrospective"
```

## 参数格式

| 参数 | 格式 | 说明 |
| --- | --- | --- |
| `--participant` | `成员1|成员2` | 参会人，至少 1 人 |
| `--input` | `材料名|READY/MISSING|说明` | 会前输入材料；存在 `MISSING` 时输出 `BLOCKED` |
| `--agenda` | `议题|owner|分钟` | 会议议题，至少 1 项 |
| `--decision` | `决策主题|owner|选项1,选项2` | 需要会上确认的决策 |
| `--action` | `任务|owner|截止日期|来源` | 会后行动项；缺 owner 或截止日期时输出 `BLOCKED` |

## 输出字段

| 字段 | 说明 |
| --- | --- |
| `mode` | 固定为 `QUALITY_REVIEW_MEETING_PACK` |
| `status` | `READY` 或 `BLOCKED` |
| `summary.agendaMinutes` | 议程总时长 |
| `summary.decisionCount` | 待确认决策数量 |
| `summary.actionItemCount` | 会后行动项数量 |
| `summary.missingInputCount` | 缺失输入材料数量 |
| `blockers` | 阻断会议有效开展的问题 |

## 当前建议议程

1. 确认 Week 8 稳定化 backlog：从月度审计和前七周复盘中挑出必须收口的项。
2. 确认团队侧流程 owner：AI 代码守护人、分支保护、PR 审查规则。
3. 确认合并策略：处理 main 落后远端 61 个提交的风险。
4. 确认下季度质量目标：把未完成的流程、可观测性和发布能力转成季度行动项。

## 阻断规则

- 没有参会人：`BLOCKED`
- 没有议程：`BLOCKED`
- 输入材料缺失：`BLOCKED`
- 行动项缺 owner 或截止日期：`BLOCKED`

这些规则的目的不是卡流程，而是防止“开完会没有后续”的质量债反弹。
