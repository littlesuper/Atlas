# 下一季度质量计划

> 用途：把 Week 8 的月度审计、前七周复盘和质量回顾会行动项，转成下一季度可执行的质量路线图。

## 生成命令

```bash
npm run quality:quarter-plan --workspace=server -- \
  --quarter "2026 Q2" \
  --theme "流程闭环|生产可观测性|发布安全" \
  --goal "完成团队侧流程闭环|AI 代码守护人|P0|Week 1/3 gaps" \
  --goal "接入真实告警通道与 APM 选型|后端负责人|P1|Week 6 gaps" \
  --milestone "2026-05|Week 8 稳定化收口|质量回顾会,分支保护策略确认" \
  --milestone "2026-06|流程制度化|PR 审查规则,AI 守护人轮值" \
  --milestone "2026-07|生产运营强化|APM 选型,真实告警通道" \
  --risk "团队 owner 未确认|main 落后远端 61 个提交" \
  --success-metric "P0 CI 持续通过|high/critical audit = 0|质量回顾会每月执行"
```

## 参数格式

| 参数 | 格式 | 说明 |
| --- | --- | --- |
| `--theme` | `主题1|主题2` | 季度主线，至少 1 个 |
| `--goal` | `目标|owner|P0/P1/P2|来源` | 季度目标；缺 owner 时输出 `BLOCKED` |
| `--milestone` | `月份|焦点|交付物1,交付物2` | 月度里程碑，至少 1 个 |
| `--risk` | `风险1|风险2` | 季度风险 |
| `--success-metric` | `指标1|指标2` | 成功标准，至少 1 个 |

## 输出字段

| 字段 | 说明 |
| --- | --- |
| `mode` | 固定为 `QUARTERLY_QUALITY_PLAN` |
| `status` | `READY` 或 `BLOCKED` |
| `summary.p0GoalCount` | P0 目标数量 |
| `themes` | 季度质量主线 |
| `goals` | 带 owner 和来源的季度目标 |
| `milestones` | 月度焦点和交付物 |
| `risks` | 需要提前管理的风险 |
| `successMetrics` | 季度验收标准 |
| `blockers` | 阻断计划有效执行的问题 |

## 当前建议路线

| 月份 | 焦点 | 关键交付 |
| --- | --- | --- |
| 2026-05 | Week 8 稳定化收口 | 质量回顾会、分支保护策略确认、团队 owner 确认 |
| 2026-06 | 流程制度化 | PR 审查规则、AI 代码守护人轮值、需求模板常态化 |
| 2026-07 | 生产运营强化 | APM 选型、真实告警通道、灰度发布管道评估 |

## 验收口径

- P0 CI 持续通过。
- `npm audit --audit-level=high` 持续为 0 high/critical。
- 每月至少一次质量回顾会，并形成行动项 owner 与截止日期。
- Week 1/3/6 遗留的团队流程、APM、外部告警通道有明确归属。
