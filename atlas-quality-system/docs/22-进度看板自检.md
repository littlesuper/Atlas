# 进度看板自检

> 用途：守住 `PROJECT_PROGRESS.md` 的同步更新规则。每完成一个质量任务后，必须能在进度看板里找到对应验证证据和变更日志。

## 默认命令

```bash
npm run quality:progress-guard --workspace=server
```

默认检查：

| 检查项 | 默认要求 |
| --- | --- |
| 当前日期 | `PROJECT_PROGRESS.md` 中的 `当前日期` 等于 Asia/Shanghai 当天 |
| Week 8 进度 | 至少 `99%` |
| 最近验证证据 | 包含 `quality:progress-guard` |
| 变更日志 | 包含 `quality:progress-guard` |

该默认值适合检查本次新增的进度看板自检任务。

## 自定义检查

需要查看 CLI 用法时，可以运行：

```bash
npm run quality:progress-guard --workspace=server -- --help
```

该命令只输出 usage、参数、默认看板路径、Asia/Shanghai 默认日期、`YYYY-MM-DD` 日期格式、默认 99% 阈值、`0-100` 整数进度范围、默认 marker、单例参数列表、等号写法、重复 marker 说明和可复制示例，不生成 `QUALITY_PROGRESS_GUARD` JSON。
`--help` / `-h` 必须单独使用；如果和门禁参数混用，CLI 会输出一行 `ERROR: --help must be used by itself.`，避免本应执行的自检被 usage 输出覆盖。

检查任意任务时，传入对应 marker：

```bash
npm run quality:progress-guard --workspace=server -- \
  --date 2026-05-06 \
  --min-week8-progress 99 \
  --evidence "quality:final-closure" \
  --changelog "quality:final-closure"
```

可重复传入 `--evidence` 和 `--changelog`，用于要求多个命令或文档都已回填；marker 不能为空白，同一个 marker 只能提供一次。空白 marker 会输出 `ERROR: --evidence marker must not be blank. Use --help for usage.` 或 `ERROR: --changelog marker must not be blank. Use --help for usage.`；重复 marker 会输出一行 `ERROR: --evidence marker is duplicated: <marker>. Use --help for usage.` 或 `ERROR: --changelog marker is duplicated: <marker>. Use --help for usage.`，避免 required/matched 统计被空值或重复要求污染。
`--file`、`--date` 和 `--min-week8-progress` 是单例参数，同一次命令中只能提供一次；重复提供会被拒绝，避免看板路径、日期或阈值被后一个参数静默覆盖。单例重复参数错误也会带上 `Use --help for usage.`，便于操作人回到 usage 查看单例参数列表。

当 marker 本身以 `--` 开头时，使用等号写法，避免被解析为下一个 option：

```bash
npm run quality:progress-guard --workspace=server -- \
  --evidence=--update="risk|status|evidenceRef|blocker" \
  --changelog="CLI help 等号 update 示例"
```

## 输出判定

通过时输出：

```text
QUALITY_PROGRESS_GUARD / READY
```

缺少任一项时输出：

```text
QUALITY_PROGRESS_GUARD / BLOCKED
```

并列出具体缺口，例如日期未更新、Week 8 进度不足、最近验证证据缺失或变更日志缺失。

底层 `buildQualityProgressGuard` 会先校验程序化传入的 input 是否为普通对象；非对象或数组 input 会返回 `progress board input is invalid` gap，并继续按空对象暴露 content、requiredDate、minWeek8Progress 和 marker 列表等字段级缺口，避免外层坏输入遮住具体修复线索。
底层 `buildQualityProgressGuard` 会对程序化传入的 required marker 列表做类型校验、item 类型校验、trim、去空和去重；非数组的 evidence/changelog marker 列表会分别返回 `verification evidence markers are invalid` 或 `changelog markers are invalid` gap，并把对应 required 统计归零，避免非 CLI 调用把坏输入变成底层 TypeError、字符级 marker 或错误统计。数组中混入非字符串 marker item 时会分别返回 `verification evidence marker is invalid` 或 `changelog marker is invalid` gap，同时继续保留同一数组里的合法 marker 统计。
验证证据 marker 只从 `## 5. 最近验证证据` 区块里 requiredDate 当天的完整 `PASS` 表格行统计，且第一列必须是 `YYYY-MM-DD` 真实日期，行内至少包含时间、命令、结果和说明 4 列，命令列和说明列都必须是非空、非 `-` / `N/A` / `NA` / `N.A.` / `NONE` / `NOT APPLICABLE` / `NOT AVAILABLE` / `TBD` / `TODO` / `PENDING` 占位值；命令列还必须以单反引号或多反引号 inline code 命令开头，且 inline code 内部也必须是非空、非 `-` / `N/A` / `NA` / `N.A.` / `NONE` / `NOT APPLICABLE` / `NOT AVAILABLE` / `TBD` / `TODO` / `PENDING` 命令，确保验证命令可复制追踪。旧日期 PASS 行、普通说明文字即使形如 `x | y | PASS | marker`、缺少说明列的半截行、空命令、占位命令、code-formatted 占位命令、code-formatted 占位说明、N/A/NA/N.A./NONE/NOT APPLICABLE/NOT AVAILABLE/TBD/TODO/PENDING 占位说明或未 code-formatted 命令 PASS 行，或证据行日期写成 `2026-13-40`，都不会满足完成证据门禁。结果列会 trim 并做大小写归一，因此 `|  PASS  |`、`| pass |` 这类手工编辑写法仍可识别。表格行允许省略开头或结尾的 `|`，同时会忽略 inline code 内部的 `|` 和普通转义 `\|`，避免命令参数或转义文本里的管道符把结果列切错。`EXPECTED_FAIL` 行即使包含同名 marker，也只作为红灯证据记录，不会满足完成证据门禁，避免失败证据冒充完成证据。
变更日志 marker 只从 `## 7. 变更日志` 区块里 requiredDate 当天的完整表格行统计，且第一列也必须是 `YYYY-MM-DD` 真实日期，行内至少包含日期、完成事项和进度影响 3 列，完成事项列和进度影响列都必须是非空、非 `-` / `N/A` / `NA` / `N.A.` / `NONE` / `NOT APPLICABLE` / `NOT AVAILABLE` / `TBD` / `TODO` / `PENDING` 占位值；旧日期变更日志行、缺少进度影响列的半截行、空完成事项行或占位完成事项行不会满足当天 changelog marker，避免历史变更或说明文字冒充本次收口变更。
builder 会对程序化传入的 `generatedAt` 做运行时校验；非 `Date` 或非法 `Date` 会返回 `progress board generatedAt is invalid` gap，并使用当前时间生成可序列化的 `generatedAt`，避免自检输出阶段因 `toISOString` 崩溃。
builder 会先校验程序化传入的看板 `content` 是否为字符串；非字符串会被归一为空文本并返回 `progress board content is invalid` gap，同时继续列出总览、验证证据、下一步执行顺序、变更日志、当前日期和 Week 8 进度等结构缺口，避免外部脚本误传内容时只得到底层 TypeError。
看板内容开头的 UTF-8 BOM 会在解析前移除，heading 行首的 BOM 也会在匹配前忽略，避免带 BOM 的 Markdown 文件或复制粘贴内容把 required heading 误报为缺失。
builder 会要求 `## 1. 总览` 必须存在且有明确的 `## 2.` 后续标题边界；缺少总览起点会返回 `progress board overview section is missing` gap，缺少边界会返回 `progress board overview section boundary is missing` gap，避免总览解析缺失或吞掉后续章节。
builder 也会对程序化传入的 `requiredDate` 做类型校验、trim、格式校验和日历值校验；非字符串日期会返回 `progress board required date is invalid` gap，空白日期不会匹配看板日期标签前缀，而是返回 `progress board required date is blank` gap，非法格式或不可能日期会分别返回 `progress board required date format is invalid: <value>` 或 `progress board required date value is invalid: <value>` gap。日期匹配只认 `## 1. 总览` 到 `## 2.` 的总览区块中可选行首 BOM、0-3 个前导空格后的独立 `**当前日期**：YYYY-MM-DD` 行，日期值前后空白会在校验前 trim；4 空格缩进按代码块处理，后续历史备注、验证证据或表格单元格里出现同名文本不会让日期门禁误判通过。总览区块缺少当前日期标签行会返回 `progress board date line is missing` gap，避免缺行被泛化成日期未更新；当前日期标签存在但冒号后为空或只有空白会返回 `progress board date value is missing` gap，避免留空被误报为缺行；出现多条当前日期标签行会返回 `progress board date line is duplicated` gap，即使其中只有一条是合法日期，也会阻断，避免新旧日期或畸形日期并存时被静默放过；若任意重复日期行本身也有缺值、格式或日历值错误，对应 gap 会和重复日期行 gap 一起保留并去重。单条当前日期值格式错误会返回 `progress board date format is invalid: <value>` gap，不可能的日历日期会返回 `progress board date value is invalid: <value>` gap。即使程序化 requiredDate 本身空白或非法，看板日期行的缺失、缺值、重复、格式或日期值 gap 也会保留，避免调用参数缺口遮住看板结构缺口。
summary 中的 `dateMatched` 只有在程序化 requiredDate 本身通过校验且总览日期完全匹配时才会为 true；空白或非法 requiredDate 不会因为看板日期也为空而误报匹配成功。
builder 会把程序化传入的 `minWeek8Progress` 限制在 `0-100` 的整数；无效数字阈值会返回 `Week 8 required progress threshold is invalid: <value>` gap，非 number 阈值会返回 `Week 8 required progress threshold is invalid: non-number` gap，且即使看板 Week 8 行缺失或畸形也不会被结构缺口遮住，避免非 CLI 调用误降、误抬、用小数阈值偏离看板整数百分比口径，或把对象/数组渲染成 `[object Object]` 这类不稳定证据。
builder 也会校验看板必须存在 Week 8 进度行，且解析出的进度值必须是 `0-100` 的整数。Week 8 进度只从 `## 1. 总览` 到 `## 2.` 的总览区块解析，且只接受可选行首 BOM、0-3 个前导空格后的 `Week 8 [..] NN%` 形式正式进度行；4 空格缩进按代码块处理，不计入进度。进度条必须是 20 位且只能由 `#` 和 `-` 组成，`%` 后必须是空白或行尾；历史备注、验证证据、变更日志或总览说明文字里的旧 `Week 8 [..] 100%` 快照不会让进度门禁误判通过。总览区块出现多条 Week 8 行骨架会返回 `Week 8 progress line is duplicated` gap，即使其中只有一条有百分比，也会阻断，避免新旧进度或畸形进度并存时被静默取第一条；若任意重复行本身也有进度值、进度条等错误，对应 gap 会和重复行 gap 一起保留并去重。缺少进度行会返回 `Week 8 progress line is missing` gap，行首为 `Week 8` 但缺少标准空格、进度条或百分比时会返回 `Week 8 progress value is missing` gap，进度条为空会返回 `Week 8 progress bar is missing` gap，进度条含非法字符会返回 `Week 8 progress bar is invalid` gap，进度条长度错误会返回 `Week 8 progress bar length is invalid: <length>` gap，例如 `Week 8[####################] 99%` 和 `99%DONE` 会返回 `Week 8 progress value is missing` gap，`099%` 会返回 `Week 8 progress value is invalid: 099` gap，`99.0%` 会返回 `Week 8 progress value is invalid: 99.0` gap，`99.5%` 会返回 `Week 8 progress value is invalid: 99.5` gap，`-1%` 会返回 `Week 8 progress value is invalid: -1` gap，`101%` 会返回 `Week 8 progress value is invalid: 101` gap，避免缺失、缺值或非法看板进度被当成通过。
builder 会要求 `## 5. 最近验证证据` 区块存在、全篇只能出现一次，并有 `## 6.` 后续标题边界；缺少证据区块会返回 `progress board verification evidence section is missing` gap，任何后文重复出现都会返回 `progress board verification evidence section is duplicated` gap，同时继续列出缺少的 evidence marker，便于同时定位结构缺口和具体证据缺口。
builder 会要求 `## 6. 下一步执行顺序` 区块存在并有 `## 7.` 后续标题边界；缺少该区块会返回 `progress board next execution section is missing` gap，缺少后续边界会返回 `progress board next execution section boundary is missing` gap，避免执行顺序章节损坏时被相邻区块检查间接表达。
builder 的区块起止匹配只接受代码围栏外的 Markdown heading；验证证据表格、命令、说明文字或 fenced code block 中的内联/示例 `## 6.` / `## 7.` 不会被误判为章节边界，避免自检证据被提前截断。Markdown heading 允许 0-3 个前导空格，因此合法缩进的 `## 1.` 至 `## 7.` 章节不会被误报缺失；4 空格缩进仍按代码块处理。精确标题允许合法 closing hashes，因此 `## 1. 总览 ##`、`## 5. 最近验证证据 ###` 这类 ATX 写法仍会识别为正式区块；但 closing hashes 必须和标题正文用空白分隔，`## 7. 变更日志###` 不能冒充正式变更日志区块。代码围栏必须用相同类型且长度不短于打开围栏的 fence 关闭，且关闭 fence 后只能尾随空白；因此反引号围栏中的 `~~~` 示例、四反引号围栏中的三反引号示例、纯波浪号围栏（`~~~`）中的 heading 示例、以及带尾随文字的 closing fence 示例都不会让守卫提前退出围栏。围栏只在前导空格不超过 3 个时生效，4 空格缩进代码块中的 fence 文本不会开启围栏状态，避免后续真实 heading 被吞掉。反引号 opening fence 的 info string 不允许包含反引号，避免无效 opening fence 文本吞掉后续真实 heading。完整标题匹配不允许额外文字，因此 `## 7. 变更日志附录` 或 `## 7. 变更日志 草稿` 不能冒充正式的 `## 7. 变更日志` 区块。
builder 会要求 `## 7. 变更日志` 区块存在且只能出现一次；缺少变更日志区块会返回 `progress board changelog section is missing` gap，重复出现会返回 `progress board changelog section is duplicated` gap，同时继续列出缺少的 changelog marker，便于同时定位结构缺口和具体日志缺口。

如果命令参数非法，例如 `--min-week8-progress abc`，CLI 会输出一行 `ERROR: ...` 并退出，不打印 TypeScript stack trace，便于直接复制到进度看板。
非法进度阈值会输出 `--min-week8-progress must be an integer between 0 and 100. Use --help for usage.`，同时给出范围和 usage 入口；小数阈值例如 `99.5` 会被拒绝，避免整数百分比看板使用小数门槛。
未知参数会输出 `Unknown argument: <arg>. Use --help for usage.`，便于从拼写错误直接跳转到 usage。
缺少参数值时会输出 `Missing value for <arg>. Use --help for usage.`，避免操作人只看到缺值但不知道如何查看可用写法。
`--file` 和 `--min-week8-progress` 的空白值会被参数层拒绝；`--file "   "` 输出 `--file must not be blank. Use --help for usage.`，`--min-week8-progress "   "` 输出 `--min-week8-progress must not be blank. Use --help for usage.`，避免空白路径落到底层文件错误或空白数字被转成 `0`。
`--date` 必须使用 `YYYY-MM-DD` 格式且是真实日历日期；例如空白值、`2026/05/07` 或 `2026-13-40` 会被参数校验直接拒绝，不会继续进入看板日期匹配逻辑。空白日期会输出 `--date must not be blank. Use --help for usage.`；日期格式或日期值错误也会带上 `Use --help for usage.`，便于直接回到 usage 查看正确写法。
