# 收口简报

> 用途：把 `quality:closure-dashboard` 的 JSON 状态转成可复制到会议纪要或群消息的 Markdown 简报。

## 生成命令

```bash
npm run quality:closure-brief --workspace=server
```

默认输出 `QUALITY_CLOSURE_BRIEF` JSON，其中 `markdown` 字段包含：

1. 当前状态。
2. 当前焦点。
3. 下一步。
4. 建议命令。
5. 全部检查项表格。

## 当前默认焦点

默认焦点为 `blocker register`：

```text
npm run quality:blocker-register --workspace=server
```

这意味着团队需要先处理或明确接受 3 个 open human blockers，再通过 `quality:blocker-resolution` 得到 `QUALITY_BLOCKER_RESOLUTION / RESOLVED`。当前简报会把 `closure evidence pack` 和 `closure evidence handoff` 显示为 `READY`，并展示 `quality:closure-remaining-work` 作为最后 1% 的剩余 owner、证据和命令清单，再展示 `quality:closure-request-pack` 用于生成 owner 请求文本；随后再继续 evidence intake、team confirmations 和 final closure。

## 使用方式

1. 运行 `quality:closure-brief`。
2. 将 `markdown` 贴入质量回顾会纪要。
3. 会议后根据 `当前焦点` 执行下一步命令。
4. 完成后用 `quality:progress-guard` 回填本看板证据。
