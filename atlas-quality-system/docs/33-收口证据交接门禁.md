# 收口证据交接门禁

> 用途：验证 `quality:closure-evidence-pack` 生成的三条证据槽位，是否能顺利交接给 `quality:evidence-intake` 并产出 `READY_TO_CONFIRM`。它检查的是命令接口和字段格式，不替代真实人工证据。

## 生成命令

```bash
npm run quality:closure-evidence-handoff --workspace=server
```

默认输出 `QUALITY_CLOSURE_EVIDENCE_HANDOFF` JSON。

## 检查内容

| 检查 | 期望 |
| --- | --- |
| evidence pack | `QUALITY_CLOSURE_EVIDENCE_PACK / READY` |
| evidence intake | `QUALITY_EVIDENCE_INTAKE / READY_TO_CONFIRM` |
| missing topics | `0` |
| next commands | 生成 team confirmations 和 final closure 后续命令，final closure 命令必须包含 `QUALITY_CLOSURE_EVIDENCE_HANDOFF / READY`、`QUALITY_CLOSURE_REMAINING_WORK / READY` 和 `QUALITY_CLOSURE_REQUEST_PACK / READY` artifact |

## 完成标准

证据包字段齐全，且转换成 `quality:evidence-intake` confirmations 后没有 missing topic 时，输出：

```text
QUALITY_CLOSURE_EVIDENCE_HANDOFF / READY
```

如果某个证据槽位缺 owner、决策模板或 evidenceRef 模板，门禁会输出 `ACTION_REQUIRED`，并列出证据包缺字段和 evidence intake 缺 topic。
