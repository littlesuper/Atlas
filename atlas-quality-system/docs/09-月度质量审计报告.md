# 月度质量审计报告

> 用途：把 `checklists/月度质量审计清单.md` 的执行结果沉淀为可归档、可比较、可进入 CI 或例会的结构化 JSON。

## 生成命令

```bash
npm run quality:audit-report --workspace=server -- \
  --month 2026-05 \
  --overall-progress 99 \
  --current-focus "Week 8 体系巩固" \
  --completed-week "Week 2|Week 4|Week 5|Week 7" \
  --evidence "npm run lint|PASS|0 errors / 0 warnings" \
  --evidence "npm run typecheck --workspace=server -- --pretty false|PASS|server typecheck passed" \
  --evidence "npm audit --audit-level=high|PASS|high/critical = 0" \
  --evidence "团队质量回顾会|WARN|尚未安排" \
  --blocker "团队侧流程未确认|main 落后远端 61 个提交" \
  --recommendation "安排第一次质量回顾会"
```

## 参数说明

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--month` | 是 | 审计月份，建议使用 `YYYY-MM` |
| `--overall-progress` | 是 | 当前整体质量项目进度，范围 0-100 |
| `--current-focus` | 是 | 当前阶段或主要焦点 |
| `--completed-week` | 否 | 已完成阶段，支持用 `|` 分隔多个值 |
| `--evidence` | 否 | 质量证据，格式为 `名称|PASS/WARN/FAIL|说明` |
| `--blocker` | 否 | 阻塞项，支持用 `|` 分隔多个值 |
| `--recommendation` | 否 | 后续建议，支持用 `|` 分隔多个值 |

## 输出字段

| 字段 | 说明 |
| --- | --- |
| `mode` | 固定为 `MONTHLY_QUALITY_AUDIT` |
| `status` | `PASSED` 或 `ACTION_REQUIRED`；存在 blocker 或 FAIL 证据时为 `ACTION_REQUIRED` |
| `summary` | 总体进度、当前焦点和已完成阶段 |
| `evidenceSummary` | PASS/WARN/FAIL 证据数量汇总 |
| `evidence` | 本月质量证据明细 |
| `blockers` | 阻塞项 |
| `recommendations` | 后续行动建议 |

## 使用节奏

1. 每月先按 `checklists/月度质量审计清单.md` 收集数据。
2. 将本月的验证命令、生产指标、事故复盘、依赖审计和流程活动作为 `--evidence` 输入。
3. 将无法自动闭环的事项作为 `--blocker` 输入。
4. 将 JSON 输出保存到当月质量例会材料或知识库。
5. 回填 `PROJECT_PROGRESS.md`，同步 Week 8 进度与最新验证证据。
