# 100% 后补证跟踪

> 用途：在 `ATLAS_QUALITY_COMPLETION / COMPLETED` 后继续跟踪已接受风险，确保 100% 收口不等于补证动作丢失。

## 生成命令

```bash
npm run quality:post-completion-followup --workspace=server
```

该命令输出 `QUALITY_POST_COMPLETION_FOLLOWUP` JSON。状态含义：

- `ACTION_REQUIRED`：补证项 owner、截止日期和授权证据齐全，但仍处于待完成状态。
- `BLOCKED`：补证项缺 owner、截止日期、授权证据或动作描述。
- `DONE`：所有补证项均已标记完成。

需要查看 CLI 用法时，可以运行：

```bash
npm run quality:post-completion-followup --workspace=server -- --help
```

该命令只输出 usage、`--format`、`--update`、`-h, --help` 和示例命令，不生成补证 JSON，适合复制到操作记录前快速确认参数格式。
Help 输出会同时展示默认 `json` 输出格式、空格写法、等号写法、大小写归一化说明、status 枚举值、短 help 别名、`--format` 单例参数说明、重复 `--update` 的多条回填说明、每个 `risk` 只能回填一次的规则，以及 `--update` 值需要加引号的 shell 提醒，避免 CLI 实际能力和文档口径不一致。

需要贴到看板或会议纪要时，可以输出 Markdown：

```bash
npm run quality:post-completion-followup --workspace=server -- --format markdown
```

Markdown 输出包含 summary、Owner Summary、Follow-Ups 和 Deadline Alerts 四块；summary 会展示 total/open/blocked/done、`missing owner/dueDate/evidence/action`、deadline 的 `overdue/dueSoon/onTrack/done/undated` 汇总和 `deadlineAlerts` 数量，避免坏日期或缺字段只藏在明细行里。Owner Summary 的 nearest due 只采用真实有效日期，坏日期会保留在明细和 gaps 中并以 `UNDATED` 暴露。Follow-Ups 表会直接展示 `Action` 和 `Blocker` 列。表格单元格中的换行会规范为 `<br>`，`|` 会转义为 `\|`，避免 action、evidenceRef 或 blocker 破坏行列结构。Deadline Alerts 文本中的换行也会规范为 `<br>`。当输出状态为 `BLOCKED` 且存在 `gaps` 时，还会追加 `Gaps` 区块；Gaps 文本中的换行同样会规范为 `<br>`，方便直接复制到进度材料并保留阻塞原因。

## 截止日期健康度

每个补证项会生成 `deadlineHealth` 和 `daysUntilDue`：

- `OVERDUE`：补证项已逾期。
- `DUE_SOON`：距离截止日期不超过 5 天。
- `ON_TRACK`：距离截止日期超过 5 天。
- `DONE`：补证项已完成，不再计入到期预警。
- `UNDATED`：截止日期缺失或格式不是 `YYYY-MM-DD`。

聚合字段 `deadlineSummary` 会统计 overdue、dueSoon、onTrack、done、undated，并给出 `nearestDueDate`。`deadlineAlerts` 输出需要关注的逾期、临近到期和 `UNDATED` 项；缺截止日期显示 `missing due date`，格式或日期值错误显示 `invalid due date: <原始值>`。Alert 排序按严重度展示：`OVERDUE` 优先，其次 `UNDATED`，最后 `DUE_SOON`；同为 `OVERDUE` 时按逾期更久优先，同为 `DUE_SOON` 时按距离截止日更近优先，其他同严重度内保留补证清单原始顺序。

## Owner 汇总

输出中的 `ownerSummary` 按负责人聚合补证项：

| 字段 | 含义 |
| --- | --- |
| `owner` | 补证负责人 |
| `total` | 该负责人名下补证总数 |
| `open` | 待补证数量 |
| `blocked` | 阻塞数量 |
| `done` | 已完成数量 |
| `overdue` | 已逾期数量 |
| `dueSoon` | 5 天内到期数量 |
| `undated` | 缺截止日期或截止日期无效数量 |
| `alerts` | 该负责人名下会进入 Deadline Alerts 的补证数量，等于 overdue + dueSoon + undated |
| `nearestDueDate` | 该负责人最早未完成截止日期 |

默认输出中，AI 代码守护人、产品负责人、release owner 各 1 项；其中 release owner 的 `dueSoon` 为 1，最早截止日为 2026-05-10。

如果补证项缺 owner，`ownerSummary` 会把它归入 `未分派`，同时保留 `follow-up owner is missing` gap；这样负责人汇总总数不会少于补证明细总数，也能让未分派工作在看板上显性暴露。Owner Summary 同时展示 `undated` 和 `alerts`，用于定位每个负责人名下缺截止日期、截止日期无效或需要 deadline 关注的补证数量。

Owner Summary 按负责人名下 deadline 风险排序：有 `OVERDUE` 的负责人优先，其次有 `UNDATED` 的负责人，再次有 `DUE_SOON` 的负责人；同一风险层级内按 `alerts` 数量降序排列，`alerts` 相同则按 `nearestDueDate` 升序排列，没有最近截止日或最近截止日相同再保留 owner 首次出现顺序。

Markdown Follow-Ups 明细表中缺 owner 的单元格也显示为 `未分派`；底层 JSON 仍保留空 owner，并继续输出 owner 缺失 gap，避免展示层空白掩盖未分派状态。

Markdown Follow-Ups 明细表中缺 action 的单元格显示为 `未填写`；底层 JSON 仍保留空 action，并继续输出 action 缺失 gap，避免动作描述缺失被空白单元格掩盖。

Markdown Follow-Ups 明细表中缺 dueDate 的单元格显示为 `未填写`；格式错误或日期值错误仍显示原始输入值，并继续通过 dueDate 校验 gap 和 `UNDATED` 暴露。

Markdown Follow-Ups 明细表中缺 evidenceRef 的单元格显示为 `未填写`；底层 JSON 仍保留空 evidenceRef，并继续输出 evidenceRef 缺失 gap，避免证据缺失被 `-` 误读为不适用。

Markdown Follow-Ups 明细表中 `BLOCKED` 项缺 blocker 时显示为 `未填写`；OPEN/DONE 项无 blocker 仍显示 `-`，避免把条件必填阻塞原因和普通无阻塞原因混淆。

当通过 `--update` 将 `rebase/merge 策略` 标记为 `DONE` 后，release owner 的 `open` 变为 0、`done` 变为 1，且不再产生 `nearestDueDate`。

Markdown 模式同样支持状态回填：

```bash
npm run quality:post-completion-followup --workspace=server -- --format markdown --update "rebase/merge 策略|DONE|merge-plan#2026-05-10"
```

## 看板更新规则

1. 每次运行补证跟踪后，把命令结果写入 `PROJECT_PROGRESS.md` 的“验证证据”。
2. 如果新增、关闭或变更补证项，同步更新本文件和 `quality:knowledge-index`。
3. 补证跟踪状态为 `BLOCKED` 时，不应继续追加新的 100% 收口声明。
4. 出现 `OVERDUE` 或 `DUE_SOON` 时，在看板验证证据中记录 `deadlineSummary` 和 `deadlineAlerts`。
5. owner 维度发生变化时，在看板验证证据中记录 `ownerSummary` 和对应 owner。
6. 100% 进度保持不变，但接受风险必须保留 owner、dueDate、evidenceRef、action 和 deadlineHealth。

## 状态回填

当某个补证项已有真实证据时，用 `--update "risk|status|evidenceRef|blocker"` 回填状态：

```bash
npm run quality:post-completion-followup --workspace=server -- --update "rebase/merge 策略|DONE|merge-plan#2026-05-10"
```

字段规则：

- `--update` 参数必须拆成 2 到 4 段：`risk|status`、`risk|status|evidenceRef` 或 `risk|status|evidenceRef|blocker`；额外的 `|` 段会被拒绝，避免证据或 blocker 被静默截断。
- `--update` 的整段值必须加引号，因为 `|` 在 shell 中会被解释为管道；等号写法也建议写成 `--update="risk|status|evidenceRef"`。
- 同一次命令可以重复传 `--update` 回填多条补证项；重复回填同一个 risk 会在 CLI 参数层输出 `--update risk can only be provided once: <risk>` 并拒绝生成补证 JSON。
- `--format`、`--update` 等带值参数后面不能直接跟另一个 `--` option；缺值时会输出 `<arg> requires a value. Use --help for usage.`，避免下一个参数被误吞成值，并能直接跳转到 usage。
- CLI 同时支持空格写法和等号写法，例如 `--format markdown` / `--format=markdown`、`--update "risk|status|evidenceRef"` / `--update="risk|status|evidenceRef"`；`--format` 会把 `JSON`、`Markdown` 等大小写输入归一为标准 `json/markdown`，非法值会输出 `Unsupported format: <format>. Expected json|markdown.`。
- `--help` 或 `-h` 会输出 CLI 用法并正常退出，不生成补证 JSON；help 优先于其他参数校验，即使后面误带了非法 option，也会先展示用法。
- `--format` 是单例参数，同一次命令中只能提供一次；重复提供时会输出 `--format can only be provided once.`，避免 JSON/Markdown 输出意图被静默覆盖。
- CLI 参数校验失败时只输出一行 `ERROR: ...`，不再打印 TypeScript stack trace，方便直接复制到进度看板或操作记录。
- 未知参数会输出 `Unsupported argument: <arg>. Use --help for usage.`，便于从拼写错误直接跳转到 usage。
- `risk`：必须匹配默认补证项的风险名称；CLI 中为空时会输出 `--update risk is required.`。
- `status`：只能是 `OPEN`、`BLOCKED` 或 `DONE`；CLI 会把 `open`、`blocked`、`done` 这类小写输入归一为标准大写枚举；为空时会输出 `--update status is required.`，非法值会输出 `Unsupported follow-up status: <status>. Expected OPEN|BLOCKED|DONE.`。
- `evidenceRef`：真实补证证据引用；`DONE` 时必须指向可追溯材料。
- `blocker`：仅在 `BLOCKED` 时填写阻塞原因。

如果 `risk` 无法匹配，命令输出 `BLOCKED`，并在 `gaps` 中写入 `follow-up update target is missing`。

安全规则：

- 构建器输入本身必须是对象；直接调用构建器传入 `null` 等非对象值时会归一为空输入，并通过 `source mode is invalid`、`authorizationRef is missing` 和 `follow-up list is empty` 阻断。
- 源补证清单必须是非空数组；空清单或非数组输入会输出 `follow-up list is empty` 并返回 `BLOCKED`，避免没有任何补证项时误判为完成。
- 源补证清单中的每一项必须是对象；数组内混入非对象项时会输出 `follow-up item is invalid` 并返回 `BLOCKED`，同时保留其他有效补证项。
- 源补证清单中的 `risk` 必须是非空字符串；缺失或非字符串时输出 `follow-up risk is missing` 并返回 `BLOCKED`，避免补证项被静默丢弃；risk 缺失时不会继续输出无风险名的源状态或 blocker safety gaps。
- 源补证清单中的接受风险 `risk` 不能重复；重复时输出 `follow-up risk is duplicated` 并返回 `BLOCKED`，明细只保留第一条可执行定义，避免重复行污染 summary、ownerSummary 和 Markdown；重复定义不会继续输出第二条定义的源状态或 blocker safety gaps。
- 源补证清单中状态只能是 `OPEN`、`BLOCKED` 或 `DONE`；直接调用构建器传入非法 source status 时输出 `follow-up item status is invalid` 并返回 `BLOCKED`，明细状态会归一为 `OPEN`，避免非法枚举污染 summary 和 Markdown。
- 补证来源 mode 必须是 `ATLAS_QUALITY_COMPLETION`；直接调用构建器传入其他 source mode 时输出 `source mode is invalid` 并返回 `BLOCKED`。
- 补证来源必须是对象；直接调用构建器传入非对象 `source` 时会归一为空 source，并通过 `source mode is invalid` 和 `authorizationRef is missing` 阻断。
- 补证来源 `authorizationRef` 必须是非空字符串；直接调用构建器传入非字符串值时会归一为空并输出 `authorizationRef is missing`。
- `generatedAt` 必须是有效 `Date`；直接调用构建器传入 `Invalid Date` 时会回退到当前时间，避免 deadline 计算或 ISO 输出抛异常。
- 源补证清单中的文本字段会先做安全归一化；直接调用构建器传入非字符串 `action`、`owner`、`dueDate`、`evidenceRef` 或 `blocker` 时不会抛异常，而是按缺失字段进入 `gaps`。
- 源补证清单中的 `dueDate` 必须使用 `YYYY-MM-DD` 格式；格式错误时输出 `follow-up dueDate format is invalid` 并返回 `BLOCKED`，同时 deadlineHealth 保持为 `UNDATED` 便于看板定位。
- 源补证清单中的 `dueDate` 必须是真实日历日期；例如 `2026-13-40` 会输出 `follow-up dueDate value is invalid` 并返回 `BLOCKED`，同时 deadlineHealth 保持为 `UNDATED`。
- `summary.missingDueDate` 只统计空 `dueDate`；格式错误或日期值错误仍作为 dueDate 校验 gap 和 `UNDATED` 暴露，但不会和“缺截止日期”混算。
- `dueDate` 校验优先于 `DONE` 状态；即使补证项标记为 `DONE`，坏日期也会让明细状态回落为 `OPEN`，显示为 `UNDATED` 而不是 `DONE`，避免 SLA 问题被完成状态掩盖或污染 summary.done。
- 源补证清单中状态为 `DONE` 的补证项必须保留 action、owner 和 dueDate；缺失时返回 `BLOCKED`，明细状态会回落为 `OPEN`，避免不完整补证项污染完成统计。
- 源补证清单中状态为 `DONE` 的补证项不能复用完成授权引用 `chat#2026-05-06-direct-to-100`；两边都有值且相同时输出 `follow-up DONE item evidenceRef must differ from authorizationRef` 并返回 `BLOCKED`，明细状态会回落为 `OPEN`，避免授权证据伪装成真实补证完成；如果授权和证据同时缺失，只输出缺失类 gaps，避免噪音误报。
- 源补证清单中状态为 `DONE` 的补证项必须填写 `evidenceRef`；缺失时输出 `follow-up evidenceRef is missing` 并返回 `BLOCKED`，明细状态会回落为 `OPEN`，避免缺证据项污染完成统计。
- 源补证清单中状态为 `DONE` 的补证项不能填写 `blocker`；填写时输出 `follow-up DONE item blocker must be empty` 并返回 `BLOCKED`，明细状态回落为 `OPEN`，且不会把 blocker 写入明细，避免阻塞项污染完成统计。
- 源补证清单中状态为 `BLOCKED` 的补证项必须填写 `blocker`；缺失时输出 `follow-up BLOCKED item blocker is missing` 并返回 `BLOCKED`。
- 源补证清单中状态为 `OPEN` 的补证项不能填写 `blocker`；填写时输出 `follow-up OPEN item blocker must be empty` 并返回 `BLOCKED`，且不会把 blocker 写入明细。
- 直接调用构建器时，同一次输入中 `risk` 也只能回填一次；重复时输出 `follow-up update target is duplicated` 并返回 `BLOCKED`，且冲突目标不会应用任何一条 update，也不会继续输出该重复目标的字段级 update safety gaps。
- 回填目标必须存在；目标缺失时输出 `follow-up update target is missing` 并返回 `BLOCKED`，且不会继续输出该不存在目标的字段级 update safety gaps。
- 回填清单必须是数组；直接调用构建器传入非数组 `updates` 时会归一为空回填清单，保留默认补证状态且不抛异常。
- 回填清单中的每一项必须是对象；数组内混入非对象项时会输出 `follow-up update item is invalid` 并返回 `BLOCKED`，同时保留其他有效回填项。
- 回填参数中的 `risk` 必须是非空字符串；缺失或非字符串时输出 `follow-up update risk is missing` 并返回 `BLOCKED`，避免错误回填被静默丢弃；risk 缺失时不会继续输出无风险名的字段级 update safety gaps。
- 回填参数中的文本字段会先做安全归一化；直接调用构建器传入非字符串 `evidenceRef` 或 `blocker` 时不会抛异常，而是按缺失字段进入 `gaps`。
- 直接调用构建器传入非法 update status 时，输出 `follow-up update status is invalid` 并返回 `BLOCKED`；非法 update 不会覆盖原补证项状态。
- `OPEN` 回填不能携带 `evidenceRef`；携带时输出 `follow-up OPEN update evidenceRef must be empty` 并返回 `BLOCKED`，且不会把 evidenceRef 写入明细。
- `OPEN` 回填不能携带 `blocker`；携带时输出 `follow-up OPEN update blocker must be empty` 并返回 `BLOCKED`，且不会把 blocker 写入明细。
- `DONE` 回填必须显式提供新的 `evidenceRef`；缺失时输出 `follow-up DONE update evidenceRef is missing` 并返回 `BLOCKED`，且不会把补证项改为 `DONE`。
- `DONE` 回填的 `evidenceRef` 不能复用完成授权引用 `chat#2026-05-06-direct-to-100`；复用时输出 `follow-up DONE update evidenceRef must differ from authorizationRef` 并返回 `BLOCKED`。
- `DONE` 回填的 `evidenceRef` 也不能复用该补证项原始接受风险证据；复用时输出 `follow-up DONE update evidenceRef must differ from original evidenceRef` 并返回 `BLOCKED`。
- `DONE` 回填不能携带 `blocker`；携带时输出 `follow-up DONE update blocker must be empty` 并返回 `BLOCKED`，且不会把补证项改为 `DONE`。
- `BLOCKED` 回填必须显式提供 `blocker`；缺失时输出 `follow-up BLOCKED update blocker is missing` 并返回 `BLOCKED`，且不会把补证项改为 `BLOCKED`。
- `BLOCKED` 回填不能携带 `evidenceRef`；携带时输出 `follow-up BLOCKED update evidenceRef must be empty` 并返回 `BLOCKED`，且不会把 evidenceRef 写入明细。
- 合规的 `DONE` 示例可以通过，但样例证据只用于验证命令能力，不代表真实补证已经归档。
