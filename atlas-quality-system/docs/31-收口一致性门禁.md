# 收口一致性门禁

> 用途：防止 `quality:blocker-resolution`、`quality:closure-evidence-handoff`、`quality:closure-remaining-work` 和 `quality:closure-request-pack` 已接入的收口链路被后续修改打断。该门禁会检查收口顺序、仪表盘、简报、最终收口包、证据 intake 和进度看板中是否仍包含统一的 blocker resolution、证据交接、剩余工作与请求包契约。

## 生成命令

```bash
npm run quality:closure-consistency --workspace=server
```

默认输出 `QUALITY_CLOSURE_CONSISTENCY` JSON。

## 当前检查契约

| Marker | 含义 |
| --- | --- |
| `QUALITY_BLOCKER_RESOLUTION` | 机器输出 mode |
| `quality:blocker-resolution` | 可执行命令入口 |
| `RESOLVED` | 最终绿色状态 |
| `QUALITY_CLOSURE_EVIDENCE_HANDOFF` | 证据交接机器输出 mode |
| `quality:closure-evidence-handoff` | 证据交接可执行命令入口 |
| `QUALITY_CLOSURE_REMAINING_WORK` | 剩余工作清单机器输出 mode |
| `quality:closure-remaining-work` | 剩余工作清单可执行命令入口 |
| `QUALITY_CLOSURE_REQUEST_PACK` | 收口请求包机器输出 mode |
| `quality:closure-request-pack` | 收口请求包可执行命令入口 |
| `READY` | 证据交接、剩余工作、请求包和最终归档的绿色状态 |

## 默认检查面

| 检查面 | 目的 |
| --- | --- |
| closure sequence util/doc | 确保执行顺序不会跳过 blocker resolution、证据交接门禁、剩余工作清单和请求包 |
| closure dashboard util/doc | 确保仪表盘仍显示 blocker resolution、证据交接门禁、剩余工作清单和请求包 |
| closure brief util/doc | 确保会议简报仍显示 blocker resolution、证据交接门禁、剩余工作清单和请求包 |
| final closure script/doc | 确保最终归档仍要求 `RESOLVED` 与 `READY` artifact，并说明请求包前置关系 |
| evidence intake util/doc | 确保证据 intake 生成的 final-closure 命令仍带 blocker resolution、证据交接门禁、剩余工作清单和请求包前置关系 |
| progress board | 确保进度看板记录了 blocker resolution、证据交接门禁、剩余工作清单和请求包 |

## 完成标准

所有检查面都包含 required markers 时，输出：

```text
QUALITY_CLOSURE_CONSISTENCY / READY
```

任一检查面缺 marker 时，输出 `ACTION_REQUIRED` 并列出缺失项。
