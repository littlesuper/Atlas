## 🎯 这套体系的核心理念

你们的特殊性：**业务人员看不懂代码,无法判断AI输出对错**

所以这套体系的核心策略是：

1. **机器替人把关**：自动化质量门禁,无需人工判断
2. **AI审查AI**：用Claude审查Claude生成的代码
3. **流程标准化**：业务人员只需"按流程操作",不需技术判断
4. **强制门禁**：所有代码必须通过多重检查才能上线
5. **生产保护**：即使代码有bug,也要限制爆炸半径

## 🚀 快速开始（新手必看）

如果你是第一次接触这套体系,按这个顺序阅读：

1. **第一天**：阅读 `docs/01-总体方案.md`(理解全貌)
2. **第二天**：阅读 `docs/03-工作流程.md`(知道每天怎么干)
3. **第三天**：把 `templates/CLAUDE.md` 放进Atlas项目根目录
4. **第四天**：配置 `ci-config/` 里的CI/CD文件
5. **第五天**：开始用 `prompts/` 里的提示词做日常开发
6. **持续**：参考 `checklists/` 在每个关键节点自检

## ⚠️ 必须立即做的5件事

如果Atlas现在还没有质量保障,这5件事是**底线**：

- [ ] **指定一位"AI代码守护者"**：部门内挑一位最懂技术的人(可兼职),负责处理本体系无法自动解决的问题
- [ ] **设置Git分支保护**：禁止直接push到main分支
- [ ] **配置基础CI检查**：使用 `ci-config/` 提供的配置
- [ ] **撤销生产数据库的危险权限**：应用账号不能有DROP/TRUNCATE权限
- [ ] **配置Sentry错误追踪**：让生产错误能被自动捕获

## 📞 寻求帮助

当遇到本系统无法解决的问题时：

1. 先查阅 `docs/05-FAQ与故障处理.md`
2. 使用 `prompts/05-Bug诊断提示词.md` 让Claude辅助诊断
3. 仍无法解决 → 联系"AI代码守护者"
4. 涉及生产事故 → 立即按 `checklists/生产事故应急清单.md` 操作

---

**记住：质量不是某一次的努力,而是每一次的坚持。**

这套体系的价值,在于让"每一次"都自动达到合格标准。
