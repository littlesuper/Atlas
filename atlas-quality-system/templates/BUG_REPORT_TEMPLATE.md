# Bug 报告模板

> ℹ️ 本模板属「质量方法论包」（`atlas-quality-system/`）。日常报缺陷请优先用：
> GitHub Issue 表单 [`.github/ISSUE_TEMPLATE/bug_report.md`](../../.github/ISSUE_TEMPLATE/bug_report.md)；
> GLM-QA 闭环用 [`docs/qa/bugs/_TEMPLATE.md`](../../docs/qa/bugs/_TEMPLATE.md)。归档规范见 [`docs/README.md`](../../docs/README.md)。

> 使用说明:
> 1. 复制本模板,在GitHub Issues或团队Wiki创建
> 2. 填写所有"必填"项
> 3. 用《05-Bug诊断提示词.md》让Claude辅助分析

## 12. 复盘(P0/P1必填)

### 12.1 根本原因
[5 Why分析,挖到最根本原因]

```
Why1: 为什么搜索报错?
→ 因为前端代码访问了 result.items 但API返回的是 result.data

Why2: 为什么前后端字段不一致?
→ 因为后端在某次重构中改了字段名,前端没同步

Why3: 为什么没同步?
→ 因为没有契约测试,前后端独立改

Why4: 为什么没有契约测试?
→ 因为体系建立时被遗漏

Why5: 为什么会被遗漏?
→ 因为初期重视功能,忽视了测试基础设施

根本原因: 缺少契约测试机制
```

### 12.2 改进措施
- [ ] 短期:加紧添加契约测试
- [ ] 中期:把契约测试加入CI必跑
- [ ] 长期:在CLAUDE.md中明确API变更规范

### 12.3 预防同类问题
[更新CLAUDE.md / 测试体系 / 流程]
