## 7. Claude生成测试代码的提示词

将以下提示词与本测试计划一起使用,让Claude生成实际的测试代码:

```
请基于以下测试计划生成完整的测试代码:

[贴入本测试计划]

要求:
1. 使用项目约定的测试框架
2. 包含所有列出的用例
3. 使用工厂模式生成测试数据
4. 不使用硬等待(sleep/setTimeout)
5. 测试相互独立(可并行)
6. 包含必要的setup/teardown
7. 添加清晰的描述
8. 遵循AAA模式(Arrange-Act-Assert)

输出文件结构:
- tests/unit/[功能].test.ts
- tests/integration/[功能].integration.test.ts
- tests/e2e/[功能].spec.ts
- tests/fixtures/[功能].fixtures.ts
```

## 9. 测试用例维护

### 9.1 何时更新测试用例
- 需求变更时
- 发现新Bug时(把Bug变成测试)
- 发现新边界场景时
- 性能要求变化时

### 9.2 何时删除测试用例
- 对应功能已删除
- 测试本身写错了(rare!)
- 用例已被其他用例覆盖

**严禁**:为了让CI过而删除/skip测试。
