# 每日开发检查清单

> **打印贴在工位旁,每天对照执行**
> 适用对象:Atlas项目所有业务人员
> 时间:每个工作日

---

## 🌅 上班第一件事(5分钟)

### 健康检查
- [ ] 看一眼 **Sentry** 大盘:今晨有无新错误?
  - 链接:https://sentry.io/yourorg/atlas
  - 关注:错误数突增、新出现的错误类型
- [ ] 看一眼 **Uptime Robot**:服务可用性如何?
  - 关注:夜间是否有down时段
- [ ] 看一眼 **CI状态**:main分支最新提交是否绿?
  - 关注:有红色失败要在团队频道沟通
- [ ] 看一下 **#incident-response** 频道:有无遗留事故未处理?

如有任何异常 → **不开始新工作**,先处理异常,通知守护者。

---

## 📋 开始工作前(每个任务前)

### 任务准备
- [ ] 我今天要做什么?(明确目标)
- [ ] 这个任务有需求文档吗?
  - 没有 → 用《01-需求澄清提示词》先写需求
  - 有但不完整 → 先完善需求
  - 有且完整 → 进入下一步
- [ ] 我对这个任务有疑问吗?
  - 有 → 在动手前问清楚(产品/守护者)
  - 没有 → 进入下一步

### 环境准备
- [ ] 拉取最新代码:`git pull origin main`
- [ ] 安装最新依赖:`npm install`(如有依赖更新)
- [ ] 创建任务分支:`git checkout -b feat/xxx`
  - 命名规范:feat/功能名 / fix/bug编号 / refactor/范围
- [ ] 启动本地环境:确保能跑起来

---

## 💻 编码过程中

### 写代码时
- [ ] 在Claude对话开头**贴入完整CLAUDE.md**
- [ ] 用《02-代码生成提示词》而非随意提问
- [ ] 验证Claude的"假设清单",有错就纠正
- [ ] 增量开发(分多步,不一次写完)
- [ ] 每写完一个小功能就跑一次

### 频繁保存
- [ ] 每30分钟 commit 一次(可以小步)
  - 即使没完成也可以commit到本地
  - 别把工作丢失
- [ ] commit message规范:`feat(xx): xxx`

### 警惕红旗信号
看到以下情况,**停下来**思考:

🚩 Claude生成了我看不懂的"复杂"代码
🚩 Claude修改了我没要求修改的文件
🚩 Claude要我执行 `rm`、`drop`、`force` 命令
🚩 Claude说"这部分不用测试"
🚩 Claude说"我假设了xxx"但没确认
🚩 Claude生成了用 `Math.random()` 做安全的代码
🚩 Claude加了我没要求的"额外功能"

→ 看到红旗:**不要继续**,问清楚再说。

## 🧪 提交代码前(每次commit/push前)

### 自检清单
- [ ] 代码完整运行通过(本地启动正常)
- [ ] 编辑器无红色错误提示
- [ ] **跑过单元测试**:`npm test`
- [ ] **跑过 lint**:`npm run lint`
- [ ] **跑过 typecheck**:`npm run typecheck`
- [ ] 没有 `console.log` / `print` 调试输出
- [ ] 没有硬编码的密钥/密码
- [ ] 没有 `TODO` / `FIXME` 留下
- [ ] 没有注释掉的死代码
- [ ] 文件中不必要的空行被清理

### Git礼仪
- [ ] commit message清晰描述**做了什么**(而非"修改文件")
- [ ] 一个commit只做一件事(避免巨型commit)
- [ ] 不要commit不该commit的:
  - .env文件
  - 个人IDE配置
  - 临时调试文件
  - 大文件(>1MB)

执行:`git commit`(pre-commit会自动运行检查,如果失败就修复)

## 🔍 PR提交前

### 必做事项
- [ ] **代码经过《03-代码审查提示词》审查**
  - 必须**新对话**进行
  - 🔴问题必须修复
  - 🟠问题强烈建议修复
- [ ] 配套测试已生成(用《04-测试生成提示词》)
- [ ] 测试覆盖率达标(本地用 `npm run test:coverage` 看)
- [ ] PR描述按模板填写(关联需求、变更内容、风险)
- [ ] 自我审视:我对这个PR有信心吗?

### 推送
- [ ] `git push origin feat/xxx`
- [ ] 在GitHub创建PR
- [ ] 等待CI运行(约10-15分钟)
- [ ] CI失败 → 看日志 → 修复 → 重新push

## ⏰ CI跑的时候

**不要干等,继续做下一个任务的需求澄清**:
- 用CI的时间读下一个需求
- 用CI的时间澄清需求
- 用CI的时间设计下一个任务

CI跑完后回来:
- 全绿 → 等审查
- 有红 → 立即处理

## 🚨 发现紧急情况怎么办?

### 情况1:生产环境出现新错误
1. **立即**在 #incident-response 报告
2. **不要**自己尝试修复
3. 联系AI代码守护者
4. 按 `生产事故应急清单.md` 操作

### 情况2:发现安全漏洞
1. **不要**在公共频道讨论(避免被攻击者看到)
2. 私信告诉守护者
3. 按守护者指示操作

### 情况3:数据库异常
1. **不要**自己尝试修复
2. **不要**直接连生产数据库改
3. 立即联系守护者

### 情况4:Claude给出明显错误的建议
1. 暂停接受Claude的建议
2. 在工作日志里记录这次"AI失误"
3. 可能需要更新CLAUDE.md预防

## ❓ 常见困惑

### Q:我没改代码,只是改文档,要走完整流程吗?
A:文档(`*.md`)的修改可以简化:
- 不需要测试
- 不需要代码审查
- 但仍需CI通过(避免格式错误)

### Q:今天紧急,可以跳过审查吗?
A:**不可以**。紧急的真正含义是"必须确保不出错",而非"可以容忍错误"。

### Q:Claude生成的代码我都看不懂,怎么审查?
A:不需要你审查,**用《03-代码审查提示词》让另一个Claude审查**。这是体系的核心机制。

### Q:我今天什么都没产出,失败感很重
A:质量体系的产出不只是代码,也包括:
- 完善的需求文档
- 仔细的代码审查
- 详细的Bug复盘
这些都是有价值的工作。
